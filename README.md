# spotiya

[![Build and test](https://github.com/klockky/spotiya/actions/workflows/ci.yml/badge.svg)](https://github.com/klockky/spotiya/actions/workflows/ci.yml)

Spotify Connect и Navidrome для Яндекс Станций: музыка, голосовое управление и
TUI в одном бинарнике на Rust. Воспроизведение и подключение к Spotify
обеспечивает [librespot](https://github.com/librespot-org/librespot/tree/v0.8.0),
собственная медиатека играет через Subsonic API
[Navidrome](https://www.navidrome.org/).

Проект проверен на **Станции Мини 2** с Buildroot, glibc 2.30 и 32-битным ARM
userspace. Имя в Spotify берётся из hostname колонки. Для других моделей нужны
совместимая сборка, ALSA и проверка локального протокола Алисы; поддержка всех
моделей не заявляется.

## Возможности

- Spotify Connect, вход через приложение или короткий код на `spotify.com/pair`.
- Navidrome: поиск и воспроизведение своей библиотеки (треки, исполнители,
  альбомы, плейлисты) с тем же голосом, кнопками, TUI и спектром.
- Голосовой поиск треков и исполнителей, пауза, продолжение и смена трека.
- Общая громкость Spotify и колонки через ALSA Master.
- TUI с поиском, текущим треком, прогрессом и управлением воспроизведением.
- Кнопки, жесты, подсветка, громкость и музыкальный спектр на дисплее Мини 2.
- Автозапуск и сохранение входа после перезагрузки.

Для Spotify нужен Premium (для Navidrome нет); нужен уже работающий root-доступ к колонке. Получение root,
прошивка и первоначальная активация станции в проект не входят.

## Установка

Готовые ARMv7-сборки доступны в [артефактах Actions](https://github.com/klockky/spotiya/actions/workflows/ci.yml).
Публикация тега `v*` также создаёт [GitHub Release](https://github.com/klockky/spotiya/releases)
с архивом и `SHA256SUMS`.

На ПК распакуй архив и передай каталог на колонку:

```sh
sha256sum -c SHA256SUMS
tar -xzf spotiya-armv7-linux-gnueabihf.tar.gz
adb -s SPEAKER_IP:5555 push spotiya /tmp/
adb -s SPEAKER_IP:5555 shell sh /tmp/spotiya/scripts/install.sh
```

Установщик запускается от root на колонке. Он сохраняет предыдущие бинарник и
скрипты в `backups/`, сохраняет данные входа, устанавливает автозапуск и команду
`spotiya`. Если корневая файловая система была read-only, после установки она
возвращается в read-only.

Исполняемый файл и скрипты находятся в `/data/opt/spotify-connect`, состояние —
в `receiver-state/`, журнал — в `/tmp/spotify-connect.log`.

## Управление

Внутри `adb shell`:

```sh
spotiya                    # TUI
spotiya login              # вход по коду
spotiya play "No Surprises"      # в источнике по умолчанию
spotiya navidrome "No Surprises" # именно в Navidrome
spotiya spotify "No Surprises"   # именно в Spotify
spotiya source navidrome         # источник по умолчанию: spotify | navidrome
spotiya navidrome-setup https://music.example.com USER   # пароль со stdin
spotiya pause
spotiya resume
spotiya next
spotiya previous
spotiya volume 25
spotiya voice off
spotiya voice on
spotiya spectrum on
spotiya spectrum off
spotiya release            # освободить сеанс для штатной музыки
spotiya status
spotiya restart
```

Команды `start`, `stop` и `version` тоже доступны. `OK` означает постановку
команды в очередь; поиск и загрузка трека выполняются асинхронно.

Для управления с ПК используй `bin/spotiya`: нужны Python 3 и adb.

```sh
python3 bin/spotiya --device SPEAKER_IP:5555 tui
python3 bin/spotiya --device SPEAKER_IP:5555 login
```

Устройство можно задать через `SPOTIYA_DEVICE` или в
`~/.config/spotiya/config.json`:

```json
{"device": "SPEAKER_IP:5555"}
```

Если устройство не задано, выбирается единственное подключённое через adb.
При нескольких подключениях нужно указать устройство явно.

### TUI

| Клавиша | Действие |
| --- | --- |
| `Space` | Пауза / продолжение |
| `n` / `p` | Следующий / предыдущий трек |
| `+` / `-` | Громкость |
| `/` | Поиск в источнике по умолчанию |
| `s` | Источник по умолчанию: Spotify / Navidrome |
| `l` | Вход в Spotify по короткому коду |
| `v` | Голосовое управление вкл/выкл |
| `e` | Визуализация спектра вкл/выкл |
| `x` | Освободить сеанс для Алисы |
| `q` | Закрыть TUI, оставив музыку |

Вход по коду ждёт подтверждения до десяти минут. До подтверждения и проверки
нового входа текущий аккаунт продолжает работать. Токены не выводятся в TUI,
статус или журнал приложения.

### Navidrome

Подключение проверяется при настройке, пароль на колонке не хранится: в
`receiver-state/navidrome.json` (права 0600) лежит только salt и md5-токен
Subsonic. В интерактивной `adb shell` пароль вводится без эха:

```sh
spotiya navidrome-setup https://music.example.com USER
```

С ПК: `python3 bin/spotiya --device SPEAKER_IP:5555 navidrome-setup URL USER`
(пароль запрашивается локально и передаётся через stdin adb, не в командной
строке). Для неинтерактивной настройки: `printf '%s\n' "$PW" | spotiya navidrome-setup URL USER`.

Необязательные поля `navidrome.json`: `"format"` (`"mp3"` по умолчанию —
сервер перекодирует поток; `"raw"` — оригинал без перекодирования),
`"max_bitrate"` (кбит/с для `mp3`, по умолчанию 256) и `"scrobble"`
(`true` по умолчанию: «сейчас играет» и учёт прослушивания в Navidrome).
После правки файла выполни `spotiya restart`.

Запрос ищется так: точное имя плейлиста, исполнителя или альбома, затем найденные
песни, затем ближайший исполнитель или альбом. Исполнитель — до пяти альбомов,
очередь не длиннее 500 треков. Источник по умолчанию выбирают `spotiya source …`
и клавиша `s`; в голосе его можно назвать: «включи Radiohead в навидроме»,
«поставь Земфира из спотифая».

Трек скачивается во временный файл в `/tmp/spotiya/navidrome` (`/tmp` колонки,
вероятно, расположен в оперативной памяти) и начинает играть после первых ~200 КБ; следующий трек докачивается заранее.
Поэтому при `"format": "raw"` большие lossless-файлы занимают заметную часть RAM
(до 160 МБ на трек, это жёсткий предел). Декодируются mp3, flac, ogg/vorbis,
aac/m4a, alac и wav; opus — только через перекодирование сервером. Частоты
отличные от 44,1 кГц приводятся линейной интерполяцией, ReplayGain не применяется.
Очередь Navidrome хранится в памяти: после перезапуска «включи музыку» её не
восстановит. Одновременно играет один источник: запуск одного ставит на паузу
или останавливает другой.

### Голос и кнопки

Примеры: «Алиса, включи Radiohead», «включи песню No Surprises», «останови
музыку», «продолжи музыку», «следующий трек».

Голосовые команды управляют активным источником (Spotify или Navidrome).
Приёмник получает окончательный текст распознавания из локального IPC Алисы
на `127.0.0.1:9875`, отменяет штатный музыкальный ответ и передаёт запрос
существующему сеансу librespot. Собственное распознавание микрофона не используется.
Пока играет Spotify, штатный музыкальный плеер периодически ставится на паузу,
чтобы дорожки не накладывались. Голосовые фразы в журнал не записываются.

На Мини 2 центральная кнопка управляет паузой; `+`/`−` меняют громкость;
жесты Алиса → `+`/`−` переключают треки. Есть короткие эффекты кольца и вывод
громкости `0–100` на дисплей. Профиль включается только при наличии sysfs-интерфейса
Мини 2. Кнопка отключения микрофона не перехватывается.

### Спектр на дисплее

На Мини 2 клавиша `e` в TUI или команда `spotiya spectrum on` включает четыре
столбца спектра: басы слева, высокие частоты справа (100, 400, 1600 и 6400 Гц).
Они обновляются 20 раз в секунду по звуку Spotify. Это визуализация;
эквализация и сами аудиоданные не меняются.

Изменение громкости на две секунды показывает проценты поверх спектра.
На паузе, при отключении визуализации и завершении Spotify возвращаются часы.
Штатные анимации имеют приоритет. Настройка сохраняется после перезапуска;
при первой установке визуализация выключена. Для других моделей TUI показывает
`unavailable`, пока для их дисплея не добавлен профиль. При выключенной
визуализации анализ звука не выполняется.

Разбор музыкальных фраз экспериментальный. Необычные имена устройств умного
дома могут быть приняты за музыкальный запрос. Альбомы и плейлисты пока
обрабатываются как текстовый поиск. После перезапуска «включи музыку» запускает
последний трек сначала; очередь и позиция не сохраняются.

## Сборка

На Linux с x86_64 нужны Rust/rustup, C-компилятор, make, pkg-config, curl и bzip2.
Для локальных Rust-тестов нужны заголовки ALSA (`libasound2-dev` в Debian/Ubuntu).

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
make -C controls/mini2 check

scripts/bootstrap-arm.sh
scripts/build-arm.sh
scripts/package.sh
```

ARM-сборка использует Bootlin GCC 8.4 / glibc 2.30 и ALSA 1.1.8. Загрузки
проверяются по SHA-256; Rust и зависимости зафиксированы в `rust-toolchain.toml`
и `Cargo.lock`. На колонке используются её системные `libasound.so.2` и glibc;
ALSA из сборочного sysroot в пакет не включается.

По умолчанию собирается ARMv7 hard-float с настройкой CPU Cortex-A53.
Пути можно переопределить через `SPOTIYA_CACHE`, `SPOTIYA_TOOLCHAIN`,
`SPOTIYA_ALSA_SYSROOT`; CPU — через `SPOTIYA_TARGET_CPU`. Это не гарантирует
совместимость с другой моделью или Android/bionic.

CI выполняет Rust fmt/clippy/tests, C-тесты с ASan/UBSan, ShellCheck,
проверку Python launcher, ARM-сборку и создание установочного архива.
