# spotiya

[![Build and test](https://github.com/klockky/spotiya/actions/workflows/ci.yml/badge.svg)](https://github.com/klockky/spotiya/actions/workflows/ci.yml)

Spotify Connect для Яндекс Станций: музыка, голосовое управление и TUI в одном
интерфейсе на Rust. Для Spotify используется официальный
[Spotify Soloist](https://github.com/spotify/soloist), установленный отдельным дополнением.

> [!IMPORTANT]
> Интеграция Soloist экспериментальная; проверена на Мини 2.
> В новой сборке backend по умолчанию — Soloist. Его исполняемый файл и личный
> API key устанавливаются отдельно.
> На Мини 2 проверены подключение, звук, пауза и повторное подключение через
> Spotify Connect. Передача звука между дополнениями ещё требует проверки.

### Установка Spotify Soloist

```sh
spotiya addon install soloist
spotiya backend soloist
spotiya restart
```

В TUI откройте `a` (дополнения), выберите **Spotify Soloist** и нажмите Enter.
После успешной установки CLI и TUI запрашивают API-ключ со скрытым вводом.
Если ключ уже сохранён, обновление сохраняет его и повторно не спрашивает.
В TUI Enter на установленном Soloist открывает ввод нового ключа; Esc отменяет ввод.
Без интерактивного терминала установка завершается с инструкцией: выполните
`/data/opt/solo/set-key.sh`, затем `spotiya retry`. Отмена ввода не удаляет Soloist.
Команда установки и TUI скачивают пакет совместимости из GitHub Releases для
текущей версии Spotiya, а сам официальный клиент — напрямую с
`soloist-builds.spotifycdn.com`. Для обновления: `u` в списке дополнений или повторно
`spotiya addon install soloist`, затем `spotiya retry`. Ключ и данные входа сохраняются.
Новая версия сначала проверяется; при нехватке места/ошибке загрузки старая остаётся.
Для каждой версии Spotiya нужен пакет совместимости из того же релиза.

Ключ создаётся в [Spotify for Developers](https://developer.spotify.com/dashboard/soloist)
действующим Premium-аккаунтом. Spotiya скрывает ввод и сохраняет ключ с правами `0600`;
не передавайте ключ в чат или аргумент команды Spotiya. Для записи из приватного файла:
`spotiya soloist key < /path/to/private-key-file`.
После запуска выберите колонку в Spotify Connect в приложении Spotify.
После замены ключа можно выполнить `spotiya retry`.

В статусе и TUI отображаются ошибки Soloist. Кнопки и команды паузы,
продолжения, смены трека и громкости
передаются в локальный WebSocket API Soloist. `spotiya play spotify:track:…` принимает
также URI альбома, плейлиста и эпизода. У Soloist нет текстового поиска; запрос
(«включи …», `spotiya play название`) можно искать через Spotify Web API — см.
[«Голосовой поиск с Soloist»](#голосовой-поиск-с-soloist). Спектр Soloist работает с нашим apulse: четыре уровня частотных полос
передаются в Spotiya без передачи аудио; включение и выключение доступны в TUI. AirPlay/YouTube используют прежние службы, но совместный
аудиовывод с Soloist пока не проверен на музыке.

Выбор хранится в `receiver-state/spotify-backend`, данные и ключ Soloist — отдельно
в `receiver-state/soloist`. Файл `soloist/launcher` в этом каталоге может задавать
абсолютный путь к launcher; по умолчанию используется `/data/opt/solo/run.sh`.

Подготовка runtime для старой glibc описана в [soloist/README.md](soloist/README.md).
Официальный Soloist не включается в архивы Spotiya и не загружается в наши GitHub Releases.

### Голосовой поиск с Soloist

Soloist принимает только готовые URI. Если backend — Soloist и запрос не является URI, Spotiya ищет
его через Web API (`/v1/search`, тип `track`, первый результат) и передаёт Soloist найденный
`spotify:track:…`. Без файла с ключами поведение прежнее: запрос отклоняется с ошибкой в статусе.

Настройка:

1. В [Spotify for Developers](https://developer.spotify.com/dashboard) создайте приложение
   (Redirect URI любой, например `http://127.0.0.1:8888/callback`; API — Web API).
2. Запишите Client ID и Client secret двумя строками в
   `/data/opt/spotify-connect/receiver-state/soloist/webapi` и выполните `chmod 600` на этот файл.
3. `spotiya restart`.

Используется вход client credentials: доступ к аккаунту не запрашивается, токен хранится только в памяти.
Проверка без голоса: `spotiya play radiohead`; результат поиска пишется в `/tmp/spotify-connect.log`
(`voice: search "…" -> исполнитель - трек`).

Ограничения: всегда запускается один трек — первый в выдаче; «включи альбом …» и «включи плейлист …»
тоже находят трек. Поиск занимает около секунды, за это время Алиса может успеть начать свой ответ.

## Быстрая установка и обновление

В **root-терминале самой колонки** (SSH или `adb shell`) вставьте строку целиком,
**вместе со скобками**, и нажмите Enter:

```sh
(set -e; d=$(mktemp -d /tmp/spotiya.XXXXXX); trap 'rm -rf "$d"' EXIT; cd "$d"; echo 'Downloading Spotiya...'; get() { LD_LIBRARY_PATH=/system/vendor/quasar/libs /system/vendor/quasar/maind --gst-launch "souphttpsrc location=https://github.com/klockky/spotiya/releases/latest/download/$1 ssl-strict=true ssl-ca-file=/etc/ssl/certs/ca-certificates.crt iradio-mode=false timeout=15 retries=1 ! filesink location=$1" >log 2>&1 && grep -Fq 'EOS: end of stream' log && ! grep -Fq 'ERROR from ' log && [ -s "$1" ]; }; get INSTALL_SHA256SUMS && get install.sh || { echo 'Installer download failed.' >&2; exit 1; }; [ "$(wc -l <INSTALL_SHA256SUMS)" -eq 1 ] && grep -Eqx '[0-9a-f]{64}  install\.sh' INSTALL_SHA256SUMS && sha256sum -c INSTALL_SHA256SUMS || { echo 'Installer checksum mismatch.' >&2; exit 1; }; sh install.sh)
```

Команда открывает интерактивное меню: установка или обновление до последнего
стабильного [релиза GitHub](https://github.com/klockky/spotiya/releases/latest),
проверка совместимости без установки и полное удаление. Выберите пункт цифрой
и нажмите Enter; Enter без выбора или конец ввода отменяет действие.
При установке и обновлении вход в аккаунт, настройки, профили и дополнения
сохраняются. При первой установке добавляются команда `spotiya` и автозапуск;
при обновлении сохраняется состояние
службы. Во время загрузки команда выводит сообщение — дождитесь результата.

После установки откройте интерфейс:

```sh
spotiya tui
```

Soloist, AirPlay и YouTube можно установить через `spotiya addons`. Нужны root-доступ и
Spotify Premium. Быстрый способ проверен на **Мини 2**; для прошивок без подходящего
`maind --gst-launch` доступна [установка через ПК](#через-пк).

## Поддерживаемые устройства

Проект поддерживает **первую Мини (YNDX-0004, `yandexmini`)** с glibc 2.23
и **Мини 2** с glibc 2.30. Обе используют Buildroot и 32-битный ARM
userspace. Soloist проверен на Мини 2; на первой Мини его работу пока нужно проверить.
Имя в Spotify берётся из hostname колонки. Для других моделей нужны
совместимая сборка, ALSA и проверка локального протокола Алисы; поддержка всех
моделей не заявляется.

## Возможности

- Spotify Connect через официальный клиент, подключение из приложения Spotify.
- Голосовые команды паузы, продолжения и смены трека.
- Общая громкость Spotify и колонки через ALSA Master.
- TUI с текущим треком, прогрессом и управлением воспроизведением.
- Кнопки, жесты, подсветка, громкость и музыкальный спектр на дисплее Мини 2.
- Автозапуск, восстановление процесса после сбоя и сохранение входа.
- Показ ошибок подключения с явным повтором из TUI.
- Профили устройства: ALSA, локальный IPC Алисы, кнопки, кольцо и дисплей.
- Диагностика с отчётом без токенов и обновление из GitHub Releases с откатом.
- Дополнения: Spotify Soloist, AirPlay 2 и YouTube (каст из приложений и ссылки из TUI).

Нужны Spotify Premium и уже работающий root-доступ к колонке. Получение root,
прошивка и первоначальная активация станции в проект не входят.

## Установка

Для установки или обновления прямо на колонке используйте [быструю команду](#быстрая-установка-и-обновление)
в начале README. Если Spotiya уже установлена, достаточно:

```sh
spotiya update
```

Команда использует последний стабильный релиз из GitHub Releases. Если версия
уже актуальна, переустановка и перезапуск приёмника не выполняются.

### Удаление

В root-терминале колонки выполните:

```sh
spotiya uninstall
```

Введите `uninstall` для подтверждения. Приёмник и дополнения остановятся;
будут удалены автозапуск, команда `spotiya`, все дополнения, сохранённый вход,
настройки, профили, бэкапы и журналы Spotiya. Штатная Алиса и её данные сохраняются.
Если остановить процессы не удалось, файлы установки не удаляются.

Для автоматизации: `spotiya uninstall --yes` (без запроса подтверждения).
Полное удаление также доступно в меню быстрой настройки. Для старых версий без
команды удаления установщик скачает текущий пакет и запустит из него удаление,
не устанавливая его поверх старого.

Скачанный `install.sh` без аргументов открывает меню. Для запуска без меню:
`sh install.sh --install`, `sh install.sh --check` или
`sh install.sh --uninstall --yes`.

### Через ПК

Готовые ARMv7-сборки доступны в [GitHub Releases](https://github.com/klockky/spotiya/releases)
и [артефактах Actions](https://github.com/klockky/spotiya/actions/workflows/ci.yml).

На ПК распакуй архив и передай каталог на колонку:

```sh
sha256sum -c SHA256SUMS
tar -xzf spotiya-armv7-linux-gnueabihf.tar.gz
adb -s SPEAKER_IP:5555 push spotiya /tmp/
adb -s SPEAKER_IP:5555 shell sh /tmp/spotiya/scripts/install.sh
```

Установщик запускается от root на колонке. Он проверяет бинарник, профиль и свободное место, сохраняет предыдущие бинарник,
скрипты и встроенные профили в `backups/`, устанавливает автозапуск и команду
`spotiya`. Если корневая файловая система была read-only, после установки она
возвращается в read-only. При ошибке установки или запуска восстанавливается
предыдущая версия. Данные входа и пользовательские профили сохраняются.
При первой установке служба запускается; при обновлении сохраняется её состояние:
работающий приёмник перезапускается, остановленный остаётся остановленным.

Исполняемый файл и скрипты находятся в `/data/opt/spotify-connect`, состояние —
в `receiver-state/`, журнал — в `/tmp/spotify-connect.log`.

## Профили устройств

`spotiya profiles` показывает встроенные и пользовательские профили, `spotiya profile` — выбранную
конфигурацию и обнаруженные возможности. Эти команды доступны без запуска
приёмника; профиль работающего приёмника также виден в TUI.

- `mini1` — первая Мини: штатная ALSA, общая громкость `Master` и Quasar IPC.
  Допустим также выбор по имени `yandexmini`.
- `mini2` — проверенный профиль Мини 2 с Quasar IPC и драйвером её кнопок,
  шестисегментного RGB-кольца и четырёхразрядного дисплея.
- `generic` — Spotify Connect через ALSA без штатного IPC и физического управления.
- `auto` — использует `receiver-state/profile.json`, если файл существует;
  иначе использует `common.deviceType` из системного `quasar.cfg` и device tree.
  `yandexmini` выбирает `mini1`, `yandexmini_2` — `mini2`; неизвестные модели получают `generic`.

У первой Мини отдельный драйвер датчика жестов и подсветки пока не включён.
Кнопка микрофона и штатные жесты остаются у Алисы; изменение общего `Master`
подхватывается приёмником. Экрана у этой модели нет. Фирменная ALSA-библиотека
реализует виртуальный `default`, поэтому профиль не подменяет его прямым `hw`.

Кнопки, кольцо и дисплей проверяются независимо. Для кольца и дисплея должны
существовать все нужные sysfs-каналы; для кнопок Мини 2 проверяется имя input-устройства.
Отсутствующая возможность отключается. Голосовое управление в общем профиле
показывается как `unavailable`; команды паузы штатному плееру не отправляются.

В TUI нажми `d`, выбери профиль стрелками или `j`/`k` и подтверди Enter.
Из терминала: `spotiya profile select mini1`, `spotiya profile select mini2`, `spotiya profile select generic`
или `spotiya profile select auto`. Выбор сохраняется при обновлениях и перезагрузках.
Работающий приёмник перезапускается; воспроизведение при этом прекращается.
Остановленный приёмник остаётся остановленным. При неудачном запуске возвращается
предыдущий выбор и выполняется попытка восстановить приёмник.

Для другой колонки положи JSON в `/data/opt/spotify-connect/profiles/`:
он появится в меню. Его можно выбрать по `id` или командой
`spotiya profile select /путь/к/профилю.json`. Выбранный файл сохраняется
как копия в `receiver-state/profile-selection.json`, поэтому удаление исходника
не ломает запуск. После редактирования исходного JSON выбери его повторно.
Встроенные варианты имеют приоритет над одноимёнными пользовательскими `id`.

Для прежней настройки через `receiver-state/profile.json` выбери `auto`.
Параметр бинарника `--profile ID_OR_JSON` переопределяет сохранённый выбор только
для текущего запуска. Новый профиль описывает ALSA, Quasar IPC и поддерживаемый
драйвер; для другой схемы кнопок или дисплея может потребоваться новый драйвер.
Ошибки JSON и неизвестные поля останавливают запуск; скрытого перехода к другому
профилю при ошибке нет.

Пример собственного аудиопрофиля; значения ALSA выбираются на целевой колонке:

```json
{
  "version": 1,
  "id": "my-station",
  "name": "My Station",
  "audio": {
    "device": "plughw:0,0",
    "format": "S16",
    "mixer_device": "hw:0",
    "mixer_control": "PCM",
    "mixer_index": 0,
    "mixer_channel": "mono"
  },
  "voice": null,
  "controls": null
}
```

Если станция использует совместимый Quasar IPC, поле `voice` задаётся как
`{"protocol":"quasar","address":"127.0.0.1:9875"}` с её локальным адресом.
В профиле Мини 2 вынесены `input_device`, `input_name`, коды трёх кнопок,
`ring_prefix` и `display_prefix`. Неиспользуемый путь можно заменить на `null`;
визуализация работает и без input-устройства. Драйвер `mini2` предполагает
совместимые жесты, отдельное input-устройство кнопок и ту же геометрию светодиодов.
Для другого протокола экрана, подсветки или голосового IPC потребуется новый
драйвер. Профили сами по себе не добавляют поддержку Android Audio HAL или
совместимость ARM-сборки с любым userspace.

Для ручного запуска можно выбрать встроенный профиль или файл без изменения
сохранённой конфигурации:

```sh
/data/opt/spotify-connect/spotiya --profile generic --profile-info
/data/opt/spotify-connect/run.sh --profile /absolute/path/profile.json
```

Выбор передаётся дочернему процессу при автоматическом перезапуске.
Встроенные профили находятся внутри бинарника; JSON-файлы в пакете служат
готовыми образцами. Имя в списке Spotify по-прежнему берётся из hostname.

## Управление

Внутри `adb shell`:

```sh
spotiya                    # TUI
spotiya play spotify:track:4VqPOruhp5EdPBeR92t6lQ
spotiya pause
spotiya resume
spotiya retry              # повтор после серии ошибок
spotiya next
spotiya previous
spotiya volume 25
spotiya voice off
spotiya voice on
spotiya spectrum on
spotiya spectrum off
spotiya release            # освободить сеанс для штатной музыки
spotiya status
spotiya profile
spotiya profiles
spotiya profile select auto
spotiya restart
```

Команды `start`, `stop` и `version` тоже доступны. `OK` означает постановку
команды в очередь; поиск и загрузка трека выполняются асинхронно.

Для управления с ПК используй `bin/spotiya`: нужны Python 3 и adb.

```sh
python3 bin/spotiya --device SPEAKER_IP:5555 tui
```

Устройство можно задать через `SPOTIYA_DEVICE` или в
`~/.config/spotiya/config.json`:

```json
{"device": "SPEAKER_IP:5555"}
```

Если устройство не задано, выбирается единственное подключённое через adb.
При нескольких подключениях нужно указать устройство явно.

### TUI

| Клавиша | Действие |
| --- | --- |
| `Space` | Пауза / продолжение |
| `n` / `p` | Следующий / предыдущий трек |
| `+` / `-` | Громкость |
| `/` | Spotify URI или ссылка YouTube |
| `v` | Голосовое управление вкл/выкл |
| `e` | Визуализация спектра вкл/выкл |
| `r` | Повтор после серии ошибок, когда закончится пауза |
| `x` | Освободить сеанс для Алисы |
| `q` | Закрыть TUI, оставив музыку |

### Голос и кнопки

Примеры: «Алиса, останови музыку», «Алиса, хватит», «продолжи музыку», «продолжай», «следующий трек».

Приёмник получает окончательный текст распознавания из локального IPC Алисы
на `127.0.0.1:9875`, отменяет штатный музыкальный ответ и передаёт запрос
Soloist через локальный API. Поиск музыки по названию работает после настройки
[Web API](#голосовой-поиск-с-soloist).
Собственное распознавание микрофона не используется.
Пока играет Spotify, штатный музыкальный плеер периодически ставится на паузу,
чтобы дорожки не накладывались. Голосовые фразы в журнал не записываются.

Быстрые команды без слова «Алиса» приходят из штатного `CommandSpotterCapability`:
«хватит», «стоп», «пауза», «играй», «продолжай» (также «продолжи»), «дальше», «назад»
и «следующий» управляют воспроизведением. «Громче» и «тише» меняют громкость
штатными средствами; Spotiya подхватывает общий Master без второго шага громкости.
Доступность конкретной фразы зависит от прошивки и штатной модели распознавания.
Spotiya назначает действия уже распознанным фразам; добавление слова в её обработчик
само по себе не учит штатную модель распознавать новую быструю фразу.
В приложении «Дом с Алисой» должны быть включены быстрые команды для музыки
(Настройки → Ассистент → Быстрые команды).

Spotiya следит за состоянием Алисы и общей громкостью колонки через локальный IPC.
Поведение приглушения Soloist во время диалога ещё требует отдельной проверки.

На Мини 2 центральная кнопка управляет паузой; `+`/`−` меняют громкость;
жесты Алиса → `+`/`−` переключают треки. Есть короткие эффекты кольца и вывод
громкости `0–100` на дисплей. Профиль включается только при наличии sysfs-интерфейса
Мини 2. Кнопка отключения микрофона не перехватывается.

### Спектр на дисплее

На Мини 2 клавиша `e` в TUI или команда `spotiya spectrum on` включает четыре
столбца спектра: басы слева, высокие частоты справа (100, 400, 1600 и 6400 Гц).
Они обновляются 20 раз в секунду по звуку Spotify. Это визуализация;
эквализация и сами аудиоданные не меняются.

Изменение громкости на две секунды показывает проценты поверх спектра.
На паузе, при отключении визуализации и завершении Spotify возвращаются часы.
Штатные анимации имеют приоритет. Настройка сохраняется после перезапуска;
при первой установке визуализация выключена. Для других моделей TUI показывает
`unavailable`, пока для их дисплея не добавлен профиль. При выключенной
визуализации анализ звука не выполняется.

Разбор музыкальных фраз экспериментальный. Необычные имена устройств умного
дома могут быть приняты за музыкальный запрос. Альбомы и плейлисты пока
обрабатываются как текстовый поиск. После перезапуска «включи музыку» запускает
последний трек сначала; очередь и позиция не сохраняются.

## Проверка устройства и отчёт

```sh
spotiya doctor
spotiya doctor report                       # новый JSON-файл в /tmp
spotiya doctor report /tmp/my-report.json
```

`doctor` проверяет процесс и наблюдение за ним, актуальность статуса, сохранённый
профиль, ALSA-микшер, громкость и mute, Quasar IPC, свободное место и RAM,
наличие сохранённого входа, DNS и HTTPS для Spotify, входа и обновлений.
Команда не запускает приёмник, не меняет громкость и не открывает PCM-устройство.
Проверка HTTPS не запускает воспроизведение и не требует входа в Spotify.
`FAIL` даёт ненулевой код завершения; `WARN` указывает, например, на остановленную
службу или отсутствие сохранённого входа.

Для отчёта из последних 64 КиБ каждого журнала берутся только счётчики категорий:
ключ аудио, сеть, декодер, аудиоустройство, авторизация и другие предупреждения.
Историческая ошибка в журнале не означает, что она продолжается сейчас.
Исходные строки логов, токены, содержимое credentials, имя аккаунта, hostname,
названия треков и пути пользовательских профилей в JSON не копируются.
Файл создаётся с правами `0600`; существующий файл не перезаписывается.
Отчёт можно приложить к issue после копирования с колонки.

С ПК доступны те же проверки; путь отчёта относится к колонке:

```sh
python3 bin/spotiya --device SPEAKER_IP:5555 doctor report
```

## Обновление

```sh
spotiya update check                         # проверить последний стабильный релиз
spotiya update                               # установить более новую версию
spotiya update v0.8.0                         # выбрать опубликованный стабильный релиз
```

Команда скачивает ARMv7-архив и `SHA256SUMS` из GitHub Releases по HTTPS,
проверяет SHA-256, структуру архива и соответствие версии бинарника тегу.
Черновики и предварительные релизы не устанавливаются. Равная или более старая
версия пропускается. Артефакты Actions не считаются опубликованным релизом;
если релизов ещё нет, `update check` сообщает об этом без изменения устройства.
Контрольная сумма сверяется с файлом из того же релиза; отдельной подписи релиза нет.

Обновление использует тот же установщик с проверкой профиля и места, что и
ручная установка. При ошибке копирования или неготовности работающего приёмника
восстанавливаются предыдущие бинарник, скрипты и встроенные профили, затем
выполняется попытка запуска старой версии. Готовность проверяется локально;
отсутствие Интернета само по себе не вызывает откат. Обновление прерывает текущую
музыку и не возобновляет её автоматически. Остановленная служба остаётся остановленной.
Хранятся до двух последних новых копий `backups/managed-*`; старые ручные и
созданные прежними установщиками копии автоматически не удаляются.

Для установки архива, уже переданного на колонку, в том числе из Actions:

```sh
spotiya update file /tmp/spotiya-armv7-linux-gnueabihf.tar.gz /tmp/SHA256SUMS
```

Локальный вариант тоже проверяет сумму и выполняет установку с откатом;
он допускает повторную установку и возврат к более старой совместимой версии.
Формат `SHA256SUMS` должен содержать имя `spotiya-armv7-linux-gnueabihf.tar.gz`.
С ПК команды доступны через `python3 bin/spotiya --device SPEAKER_IP:5555 update …`;
пути локального варианта относятся к файлам на колонке.

## Диагностика воспроизведения

Состояние подключения и последнюю ошибку показывают `spotiya status` и TUI.
Журнал приёмника — `/tmp/spotify-connect.log`, Soloist — `/tmp/spotiya-soloist.log`.
После устранения причины ошибки выполните `spotiya retry`.

## Восстановление службы

`spotiya start` запускает режим наблюдения `--supervise` того же бинарника.
Он перезапускает приёмник после выхода с паузами 2, 4, 8, 16, 32 и максимум
60 секунд. После минуты стабильной работы задержка снова начинается с двух
секунд. Отсутствие сети не отменяет последующие попытки запуска.

`spotiya stop` останавливает и наблюдение, и приёмник; после ручной остановки
служба сама не запускается. Повторный `start` не создаёт второй экземпляр.
После сбоя самого наблюдения следующий `start` останавливает оставшийся
дочерний процесс и запускает службу заново. `run.sh` без `--supervise`
по-прежнему подходит для диагностики в переднем плане.

Журнал наблюдения — `/tmp/spotify-connect-supervisor.log`. Журнал приёмника
сохраняется между перезапусками; перед очередным запуском файл от 256 КиБ
перемещается в `/tmp/spotify-connect.log.1`. Новые скрипты устанавливаются
вместе с бинарником через `scripts/install.sh`.

## Память

Spotiya и Soloist работают отдельными процессами: для общего расхода памяти
нужно учитывать оба. RSS включает разделяемые страницы бинарников и библиотек;
для сравнения полезны также PSS и Private Dirty из `/proc/PID/smaps`.
Расход во время воспроизведения зависит от трека, очереди и включённых дополнений.

## Сборка

На Linux с x86_64 нужны Rust/rustup, Git, C-компилятор, make, pkg-config, curl, bzip2 и xz.
Для локальных Rust-тестов нужны заголовки ALSA (`libasound2-dev` в Debian/Ubuntu).

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
make -C controls/mini2 check

scripts/bootstrap-arm.sh
scripts/build-arm.sh
scripts/package.sh
```

ARM-сборка использует Linaro GCC 6.5 / glibc 2.23 и ALSA 1.1.8.
`scripts/build-arm.sh` проверяет, что бинарник не требует более новой glibc. Загрузки
проверяются по SHA-256; Rust и зависимости зафиксированы в `rust-toolchain.toml`
и `Cargo.lock`. На колонке используются её системные `libasound.so.2` и glibc;
ALSA из сборочного sysroot в пакет не включается.

По умолчанию собирается ARMv7 hard-float с настройкой CPU Cortex-A53.
Пути можно переопределить через `SPOTIYA_CACHE`, `SPOTIYA_TOOLCHAIN`,
`SPOTIYA_ALSA_SYSROOT`; CPU — через `SPOTIYA_TARGET_CPU`. Это не гарантирует
совместимость с другой моделью или Android/bionic.

CI проверяет core/audio/discovery форка на закреплённой ревизии и выполняет Rust
fmt/clippy/tests, C-тесты с ASan/UBSan, ShellCheck, проверку Python launcher,
ARM-сборку и создание установочного архива.

## AirPlay 2

Начиная с 0.9.0 Spotiya может управлять дополнительным приёмником AirPlay 2
на основе Shairport Sync. Он использует системное имя колонки и объявляет модель
`AudioAccessory5,1` для иконки HomePod mini в меню AirPlay. Набор возможностей
AirPlay остаётся прежним. Иконка зависит от отправителя и его кеша. В TUI клавиша
`a` открывает отдельный экран дополнений. Из терминала — `spotiya addons`.
В нём Enter скачивает отсутствующее дополнение из GitHub Releases. Для AirPlay
установка также включает службы; Enter у установленного AirPlay включает или
выключает их.
Отдельные команды — `spotiya airplay on` и
`spotiya airplay off`. Настройка сохраняется после перезагрузки.

AirPlay устанавливается отдельным пакетом `spotiya-airplay2-armv7.tar.gz`.
Экран показывает список дополнений, их состояние и ход загрузки. Стрелки или
`j`/`k` выбирают пункт, `Esc`/`q` возвращают к плееру, `c` отменяет установку.
Можно вернуться к плееру, пока идёт загрузка; выход из TUI отменяет её.
У установленного дополнения `u` скачивает пакет текущей версии заново и заменяет
старый, если он отличается. После обновления
AirPlay перезапустите приёмник (`spotiya restart`). Двойное нажатие `x` удаляет дополнение; AirPlay сначала
нужно выключить. Из терминала: `spotiya addon install ID` также обновляет,
`spotiya addon remove ID` удаляет.
Каталог дополнений задаётся в `src/addons.rs`, интерфейс работает со всем списком.

Пакет берётся из релиза **той же версии**, что запущенная Spotiya. Перед установкой
проверяются SHA-256 архива, манифест и отдельные бинарники. Установка не перезапускает
Spotify и не копирует файлы AirPlay в основной бинарник. При выключенном AirPlay
его четыре службы остановлены. Для прямой установки: `spotiya addon install airplay`.
Без опубликованного релиза с AirPlay экран покажет причину и позволит повторить попытку.

Базовый пакет Spotiya сохраняет прежний размер и работает без него. Внутри
AirPlay-пакета находятся Shairport Sync, NQPTP, Avahi и приватный D-Bus;
системный D-Bus и его настройки не меняются. Avahi не публикует обратные
адресные записи, чтобы не конфликтовать со штатным mDNS станции. Все процессы запускаются и
останавливаются вместе с приёмником Spotiya. При сбое одного из них стек
перезапускается с задержкой. Обновление основной Spotiya сохраняет AirPlay-пакет.

Сборка на Linux:

```sh
scripts/bootstrap-arm.sh
scripts/build-airplay.sh
```

Нужны инструменты сборки C/C++, Python 3, CMake, Autoconf, Automake, Libtool,
gettext, pkg-config, flex, bison, xxd, patch и host-программа `plistutil`.
Исходники зависимостей закреплены в `airplay/sources.json` с SHA256;
ревизии Shairport Sync и NQPTP закреплены в `airplay/fetch.py`.

Собранный пакет ставится той же командой, что и пакет из релиза; версия Spotiya
на станции должна совпадать с версией пакета:

```sh
adb -s DEVICE push dist/spotiya-airplay2-armv7.tar.gz dist/AIRPLAY_SHA256SUMS /tmp/
adb -s DEVICE shell spotiya addon file airplay /tmp/spotiya-airplay2-armv7.tar.gz /tmp/AIRPLAY_SHA256SUMS
adb -s DEVICE shell spotiya airplay on
```

Выберите системное имя станции в меню AirPlay на iPhone, iPad или Mac в той же
локальной сети. При начале AirPlay Spotify освобождает аудиовыход. При запуске
Spotify AirPlay-сессия завершается, а приёмник снова становится доступен.
Громкость AirPlay меняет общий уровень колонки. `release`/`x` и пауза в TUI
завершают AirPlay-сессию; продолжение и смена трека управляются на отправителе.
Спектр на дисплее пока обрабатывает только Spotify.

Лог дополнительных служб: `/tmp/spotiya-airplay.log`. В `spotiya status` есть
поля `airplay_available`, `airplay_enabled`, `airplay_running`, `airplay_active`
и `airplay_error`. Отдельная ошибка AirPlay не останавливает Spotify Connect.

Основной пакет собран для ARMv7 hard-float с glibc 2.23 и системной ALSA;
он подходит для первой Мини и Мини 2. Опциональные AirPlay-компоненты
необходимо отдельно проверять на конкретной станции.

## YouTube

Дополнение `youtube` принимает каст из приложений YouTube и YouTube Music (колонка
видна в меню трансляции под своим системным именем) и играет ссылки: их можно вставить в обычный поиск TUI (`/`) или в отдельную строку
`y`, из терминала — `spotiya youtube ССЫЛКА` или `spotiya play ССЫЛКА`. Ссылка
YouTube в поиске никогда не уходит в Spotify. Понимаются
`youtu.be/…`, `watch?v=…`, `/shorts/…` и голый идентификатор видео. Звучит только
аудиодорожка.

Установка и включение — через экран дополнений или командами
`spotiya addon install youtube` и `spotiya youtube on`/`off`. Пакет
`spotiya-youtube-armv7.tar.gz` занимает около 1,5 МБ; пока дополнение выключено,
его процесс не запущен.

Аккаунт YouTube на колонке не нужен и не используется: выбирает видео телефон, а
звук колонка получает как анонимный мобильный веб-клиент, то есть так же, как
разлогиненный браузер. Чтобы YouTube не обрывал поток на первой минуте, колонка сама
получает PO-токен: проверка BotGuard и расшифровка ссылок из плеера YouTube
выполняются во встроенном QuickJS. Подготовленный плеер кешируется в
`receiver-state/youtube/cache` и пересобирается только при смене его версии.
Видео, для которых нужен вход (приватные, для участников, с возрастным
ограничением), так не воспроизводятся.

Колонку YouTube делит со Spotify и Алисой так же, как AirPlay: с первым звуком
трека Spotify останавливается, а Алиса ставится на паузу; запуск Spotify, наоборот,
останавливает YouTube. Пауза, продолжение и смена трека работают с кнопок колонки,
из TUI (пробел, `n`, `p`) и голосом; громкость кнопками и с телефона меняет общий
ALSA Master. TUI показывает состояние `YOUTUBE` и название ролика, спектр работает в TUI и на дисплее так же, как для Spotify. Остановка всегда идёт через
штатное закрытие ALSA: процесс, убитый посреди записи, может оставить общий
микшер dmix в состоянии, в котором замолкает вся колонка вместе с Алисой.

Тяжёлый JS-контекст плеера освобождается после обработки ссылки. На диске остаются
подготовленный скрипт и скомпилированный байткод QuickJS: следующие треки загружают
байткод без повторного разбора JS. Кэш привязан к исходнику и сборке аддона;
при несовпадении или повреждении он пересоздаётся. На тестовом плеере кэш байткода
занимает около 9 МиБ на диске.

В локальном тесте обработчика на ПК после обработки оставалось 11–12 МиБ RSS.
Пик составлял около 33 МиБ при готовом кэше и около 43 МиБ при первой компиляции;
обработка с готовым кэшем занимала примерно 0,12 секунды.
Это не замер полного аддона на станции: её расход ОЗУ ещё нужно проверить.
Первый трек после запуска требует подготовки токена и плеера; следующие используют
сохранённый скрипт и готовый минтер токенов.

Сборка на Linux:

```sh
scripts/bootstrap-arm.sh
scripts/build-youtube.sh
```

Код DIAL, SSDP и Lounge адаптирован из [ytcast-open](https://github.com/mthwJsmith/ytcast-open)
(MIT). Уведомления ytcast-open, BgUtils, jsdom, quickjs-ng и libopus лежат в
`youtube/licenses` и входят в пакет.
